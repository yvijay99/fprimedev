## Branch Purpose

`devicemanagertest` introduces the `Managers` module — a collection of active F Prime components that manage the spacecraft's peripheral devices. Each manager runs on a rate group, communicates over a hardware bus (I2C or SPI), and exposes commands, telemetry, and events through the standard F Prime framework ports.

This branch also wires those managers into the `LedBlinker` topology alongside dedicated bus driver instances.

## Components

All manager components live in the `Managers` FPP module (`myprojectnamespace/Components/`).

### SensorManager

| | |
|---|---|
| **Device** | ICM-20649 6-axis IMU |
| **Bus** | I2C via `imuI2cDriver` |
| **Rate group** | rateGroup2 — 10 Hz |
| **Base ID** | `0x10022000` |

**Telemetry channels:** `AccelX/Y/Z` (m/s²), `GyroX/Y/Z` (deg/s), `ImuTemp` (°C)

**Commands:** `CALIBRATE_IMU` — logs `ImuCalibrationStarted`, returns OK. Calibration offset logic is a TODO.

**Events:** `ImuReadOk` (activity low), `ImuReadError(i2cStatus)` (warning high), `ImuCalibrationStarted` (activity high)

**Implementation notes:**
- Reads 14 bytes starting at `ACCEL_XOUT_H (0x3B)` in a single `busWriteRead` call
- Accel sensitivity: ÷ 8192.0 (±4g range); Gyro sensitivity: ÷ 65.5 (±500 dps range)
- Temperature formula: `(raw − 21) / 333.87 + 21`
- Only runs if `busWriteRead` output port is connected (guards against unconnected SIL runs)

### MagnetometerManager

| | |
|---|---|
| **Device** | PNI RM3100 |
| **Bus** | I2C via `magI2cDriver` |
| **Rate group** | rateGroup2 — 10 Hz |
| **Base ID** | `0x10024000` |
| **Default I2C address** | `0x20` (configurable via `configure()`) |

**Telemetry channels:** `MagX/Y/Z` (µT), `MagTemp` (°C)

**Commands:** `CALIBRATE_MAG` — logs `MagCalibrationStarted`, returns OK.

**Events:** `MagReadOk` (activity low), `MagReadError(i2cStatus)` (warning high), `MagCalibrationStarted` (activity high)

**Implementation notes:**
- Reads 9 bytes from `MX_REG (0x24)` covering X/Y/Z as 24-bit signed big-endian values
- Sensitivity: ÷ 75.0 LSB/µT (RM3100 default CCC = 200)
- `readTemperature()` currently reads from `STATUS_REG (0x34)` and always returns 0.0 — temperature decoding is a TODO
- Sign extension applied manually for all three axes

### NavigationManager

| | |
|---|---|
| **Device** | u-blox GPS module (GNSS) |
| **Bus** | I2C via `gpsI2cDriver` (address `0x42`) |
| **Rate group** | rateGroup2 — 10 Hz |
| **Base ID** | `0x10023000` |
| **Status** |  **In progress** |

**Telemetry channels:** `Latitude` (°, F64), `Longitude` (°, F64), `Altitude` (m), `GroundSpeed` (m/s), `NumSatellites`

**Commands:** `GPS_RESET` — clears fix flag, returns OK.

**Events:** `GpsFixAcquired(numSats)` (activity high), `GpsFixLost` (warning high)

**Implementation notes:**
- Sends UBX-CFG-VALSET on `configure()` to set the dynamic platform model to airborne (<4g)
- Reads NMEA data in 32-byte chunks (up to 64 attempts per cycle) via register `0xFF`
- Parses `GNRMC` (speed, fix validity) and `GNGGA` (lat/lon/alt/sats) sentences with NMEA checksum validation
- Fix threshold: `numSatellites >= MIN_SATELLITES_FOR_FIX` (defined in `.hpp`)
- Known gap: partial sentence boundary handling across I2C chunks is not fully robust — being addressed this sprint

## Topology & Rate Groups

Bus drivers and rate group assignments are defined in `LedBlinker/Top/instances.fpp` and `topology.fpp`.

### Rate Groups

| Rate Group | Frequency | Manager Members |
|---|---|---|
| `rateGroup1` | 1 Hz | `systemManager`, `radioManager` |
| `rateGroup2` | 10 Hz | `sensorManager`, `navigationManager`, `magnetometerManager` |
| `rateGroup3` | 2.5 Hz | Health, buffer managers, data products |

### Bus Driver Instances

| Instance | Type | Connected To |
|---|---|---|
| `imuI2cDriver` | `Drv.LinuxI2cDriver` | `sensorManager` |
| `magI2cDriver` | `Drv.LinuxI2cDriver` | `magnetometerManager` |
| `gpsI2cDriver` | `Drv.LinuxI2cDriver` | `navigationManager` |
| `radioSpiDriver` | `Drv.LinuxSpiDriver` | `radioManager` |

### Base ID Convention

All instances follow the pattern `0xDSSCCxxx`:
- `D` = deployment digit (`1` for this deployment)
- `SS` = subtopology (`00` for main topology)
- `CC` = component index
- `xxx` = reserved for internal component items

## Build Instructions

### Prerequisites

- Python 3.8+
- CMake ≥ 3.24.2
- F Prime v4.0.0 (pinned via `requirements.txt`)
- ARM cross-compiler or native Raspberry Pi build environment

### Setup

```bash
# Clone and initialize
git clone --branch devicemanagertest https://github.com/yvijay99/fprimedev.git
cd fprimedev

# Install Python dependencies (includes fprime-util)
pip install -r requirements.txt

# Generate build cache
fprime-util generate
```

## Build & Deploy

### 1. Build (Docker cross-compile for aarch64, skip if you have windows or you have your own toolchain)

Run this from your local machine. The Docker image handles the ARM toolchain — no local cross-compiler needed.

```bash
docker run --rm -it \
  -v /path/to/project:/project \
  nasafprime/fprime-arm \
  bash -c "cd /project && pip install -r requirements.txt && fprime-util generate aarch64-linux -f && fprime-util build aarch64-linux"
```

Outputs land at:
- Binary: `build-artifacts/aarch64-linux/LedBlinker/bin/LedBlinker`
- Dictionary: `build-artifacts/aarch64-linux/LedBlinker/dict/LedBlinkerTopologyDictionary.json`

### 2. Deploy to Pi

```bash
scp build-artifacts/aarch64-linux/LedBlinker/bin/LedBlinker <pi-user>@<pi-ip>:~/
scp build-artifacts/aarch64-linux/LedBlinker/dict/LedBlinkerTopologyDictionary.json <pi-user>@<pi-ip>:~/
```

### 3. Run on Pi

```bash
ssh <pi-user>@<pi-ip>
chmod +x LedBlinker
./LedBlinker -a 0.0.0.0 -p 50000 &
```

## Contributing / Code Review Workflow

### Branching

Work off `devicemanagertest` for anything in the `Managers` module this sprint. Do not merge to `main` until NavigationManager GPS parsing is validated on hardware.

### Commit Style

Keep commits scoped to one component or one topology change at a time. Follow the pattern already in the log:

```
add <ComponentName> (<brief description>)
wire up <feature> in topology
fix <ComponentName>: <what changed and why>
```
### Review Checklist

- [ ] Port connections in `topology.fpp` are correct — check both directions (output → input)
- [ ] New instances in `instances.fpp` have unique base IDs that don't collide with existing assignments
- [ ] `run_handler` guards against unconnected output ports before calling `_out()`
- [ ] Events use appropriate severity (`ACTIVITY_LO` for nominal, `WARNING_HI` for bus errors)
- [ ] No hardcoded I2C/SPI addresses that should be configurable via `configure()`
